# 차돈(Chadon) 제작기

이번에는 **차돈**을 만든 과정을 간단히 정리해보려고 한다.

차돈은 한 줄로 말하면 이런 프로그램이다.

~~~text
자동차 정비소의 매출/매입을 관리하는 Windows 프로그램
~~~

이름은 "자동**차**로 **돈**을 벌어보자"에서 왔다.

정비일지(RO) 등록, 고객 관리, 매입/부품 재고, 일일마감과 결산, 매출통계 그래프,
계산서/견적서 인쇄까지 정비소 하루 업무를 한 프로그램 안에서 처리하는 것이 목표였다.

![차돈 아이콘](/assets/img/chadon-icon.png)

- 공식 웹사이트: <https://chadon.mokky.store>

---

## 기술 스택은 일부러 단순하게 잡았다

사용자는 개발자가 아니라 **정비소 사장님**이다.

그래서 처음부터 조건을 이렇게 잡았다.

~~~text
설치 과정 없이 exe 하나만 실행하면 된다.
데이터는 exe 옆의 파일 하나에 다 들어간다.
서버가 죽어도 프로그램은 돌아간다.
~~~

이 조건에 맞춘 스택은 이렇다.

| 요소 | 선택 |
| --- | --- |
| 언어/UI | Python + tkinter |
| 데이터 | SQLite 단일 파일 (`data\chadon.db`) |
| 배포 | PyInstaller `--onefile` → `차돈.exe` |
| 서버 | Cloudflare Workers + KV (인증/백업/모바일 조회) |
| CI | GitHub Actions (태그 푸시 → 자동 빌드/배포) |

tkinter는 화려하진 않지만 파이썬 기본 포함이라 의존성이 없고,
SQLite는 DB 서버 없이 파일 하나로 끝난다.
"내 자료가 어디 있는지" 물으면 "exe 옆 data 폴더"라고 답할 수 있는 구조다.

프로젝트 구조는 데이터 계층과 화면을 나눴다.

~~~text
main.py               실행 진입점
chadon/
  db.py               SQLite 데이터 계층 (정비/고객/매입/부품/마감/통계)
  printing.py         HTML 인쇄 문서 생성
  backup.py           로컬+클라우드 백업/복원
  app_import.py       타 앱 자료 반입
  excel_export.py     엑셀 내보내기
  license.py          인증키 검증
  update.py           자동 업데이트 (Ed25519 서명 검증)
  ui/                 tkinter 화면
server/worker.js      Cloudflare Worker (인증/백업/모바일 서버)
~~~

## 핵심은 정비일지였다

정비소 프로그램의 중심은 결국 정비일지(RO)다.

정비 내역은 한 줄씩 **부품값과 공임을 따로 입력**하고,
금액은 `부품값 × 수량 + 공임`으로 자동 계산된다.

여기서 신경 쓴 규칙 몇 가지.

- 부품선택으로 고른 부품은 저장 시 **재고가 수량만큼 자동 차감**된다 (수정/삭제 시 복원)
- 외상매출 = 정비금액 − 계산금액으로 자동 계산
- **완결처리**하면 계산금액이 정비금액으로 채워지고, **완결취소**하면 되돌아간다

정비일지 하나만 제대로 쌓이면 일일마감, 결산, 매출통계는
전부 그 데이터에서 파생된다. 결산 화면에서는 아직 못 받은 돈을
**외상(수입)**, 아직 안 준 돈을 **외상(소비)**으로 나눠 보여준다.

## 타 앱 자료 가져오기

기존 사용자들은 Highway5/BizHigh5 같은 다른 정비 프로그램을 쓰고 있었다.

그런데 이런 프로그램의 내부 DB는 대부분 비공개(독점) 형식이라 직접 열 수 없다.
대신 어느 프로그램이든 있는 **엑셀(CSV) 내보내기** 기능을 통로로 삼았다.

~~~text
타 앱에서 CSV/XLSX 내보내기
→ 차돈 마법사에서 파일 선택
→ 열 이름(차량번호, 고객명, 정비금액...) 자동 인식
→ 매핑을 직접 수정하고 미리보기 확인
→ 반입
~~~

한글 CSV는 인코딩이 제각각이라 cp949/euc-kr/utf-8을 자동 인식하게 했고,
열 자동 인식이 틀릴 수 있으니 반입 전에 사람이 매핑을 고칠 수 있게 했다.
갈아타는 비용을 줄이는 것이 신규 사용자 확보의 절반이었다.

## 백업은 로컬 + 클라우드 이중으로

정비소 데이터는 곧 돈이다. PC가 고장 나면 몇 년치 장부가 날아간다.

그래서 백업을 두 겹으로 만들었다.

- **로컬 백업**: `data/backups/`에 저장, 최근 30개 보관
- **클라우드 백업**: DB를 gzip 압축해 Cloudflare KV에 업로드 (인증키당 1슬롯)
- **자동 백업**: 일일마감 저장 시 자동 실행 (기본 켬)

PC를 교체하면 새 PC에서 인증키 등록 후 [클라우드에서 복원] 한 번이면 끝난다.

여기에 덤으로 **모바일 조회**도 붙였다.
PC에서 조회 비밀번호를 설정하면 휴대폰 브라우저에서 정비일지/부품재고를
읽기 전용으로 볼 수 있다. 재미있는 부분은 서버가 백업 파일을 해석하지 않고,
휴대폰 브라우저 안에서 sql.js로 직접 여는 구조라는 점이다.
서버는 암호화된 통로일 뿐, 데이터 해석은 사용자 기기에서만 일어난다.

## 인증키와 자동 업데이트

판매를 전제로 한 프로그램이라 정품 인증도 필요했다.

- 인증키(`CHDN-XXXX-XXXX-XXXX`)는 최초 인증한 PC 1대에 묶인다
- 인터넷이 끊겨도 **7일간 오프라인 유예**로 정상 동작한다
- 발급/정지/기기 해제는 관리자 도구로 처리한다

자동 업데이트는 배포 채널이 곧 공격 통로가 될 수 있어서 제일 조심했다.

~~~text
앱 시작 5초 후 latest.json 확인
→ (버전 + SHA-256)에 대한 Ed25519 서명 검증
→ https + 호스트 allowlist 확인
→ 다운로드한 exe의 SHA-256 재확인
→ 전부 통과해야 교체·재시작
~~~

공개키만 앱에 내장하고 개인키는 저장소 밖에 둔다.
배포 서버가 통째로 털려도 개인키 없이는 가짜 업데이트를 설치시킬 수 없다.
미서명/위변조 파일은 설치 자체를 거부한다(fail-closed).

배포는 태그 하나로 끝난다.

~~~bash
git tag v2.0.0
git push origin v2.0.0
~~~

GitHub Actions가 exe를 빌드하고 서명해서 배포 저장소에 올리면,
몇 분 뒤 사용자 앱이 새 버전을 감지해 원클릭으로 스스로 교체된다.

## 출시 전 보안 감사

공개 배포 직전에는 전체 보안 감사를 한 번 돌렸다.

- 공개 저장소/소스 전역 비밀 스캔 → 유출 없음
- 관리자 API는 Bearer 토큰 필수, 미설정 시 전면 401(fail-closed)
- 모바일 로그인은 인증키 + PIN 2요소, PIN은 PBKDF2 해시 저장, 5회 실패 시 10분 잠금
- 토큰 비교는 전부 상수시간 비교
- 서버 블랙박스 레드팀 테스트 34/34 통과

기능을 다 만들고 나서 보니, 결국 이런 프로그램의 신뢰는
"장부가 안 날아가고, 남이 내 장부를 못 본다"는 두 문장으로 요약됐다.

## 이번 글 요약

차돈을 만들면서 한 핵심 결정은 다음과 같다.

- 사용자는 사장님이므로 exe 하나 + SQLite 파일 하나로 끝나는 구조를 지켰다.
- 정비일지 데이터 하나에서 마감/결산/통계가 전부 파생되게 만들었다.
- 타 앱 CSV 반입으로 갈아타는 비용을 줄였다.
- 백업은 로컬+클라우드 이중, 모바일 조회는 서버가 해석하지 않는 구조로 했다.
- 자동 업데이트는 Ed25519 서명 + SHA-256 재검증으로 fail-closed하게 만들었다.
- 출시 전 보안 감사와 레드팀 테스트로 마무리했다.

작은 프로그램이지만, 남의 돈 장부를 다루는 프로그램은
기능보다 **데이터가 안 죽는 구조**가 먼저라는 걸 배운 프로젝트였다.
